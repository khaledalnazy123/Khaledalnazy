# الانتقال الآمن من MovieVault v1 إلى v2

## أين بيانات النسخة القديمة؟
ليس بالضرورة داخل `Desktop\MovieVault_v1`. v1 غالبًا يخزن البيانات في:
`%LOCALAPPDATA%\MovieVault\movievault.sqlite`
أما v2 فيخزن بياناته في:
`%LOCALAPPDATA%\MovieVault\v2\movievault.sqlite`

1. افتح v1 واعمل Create Backup. انسخ ملف الـZIP إلى هارد آخر.
2. استخرج v2 إلى فولدر جديد منفصل. لا تعمل Replace لملفات v1.
3. افتح v2 ثم Settings → Import Previous Library (أو الإعلان في أول تشغيل).
4. اضغط **Auto-detect Previous Library**؛ أو **Choose Folder** وحدد فولدر v1، أو فولدر البيانات، أو **Choose Backup ZIP**.
5. اضغط **Preview Data**؛ راجع `Movies`, `Subtitles`, `IMDb titles`, `Watched folders`, `Posters`، ورقم schema. لو اخترت فولدر برنامج v1 سيبحث عن قاعدة البيانات الفعلية في Windows AppData ويخبرك بذلك.
6. اضغط **Import Previewed Data**. لا يتم تغيير أي ملف داخل v1. تبدأ نسخة SQLite مؤقتة وتُفحص سلامتها ثم تُجهّز للاستيراد.
7. أغلق v2 تمامًا وافتحه من جديد. تُفعّل النسخة أثناء بداية التشغيل فقط، بشرط أن مكتبة v2 لم يُضف إليها محتوى آخر. يتم حفظ Snapshot أمان من قاعدة v2 الفارغة قبل الاستبدال.
8. راجع الأسماء الأصلية، التعديلات اليدوية، الأنواع، الترجمات، فهرس IMDb، والصور المحلية أو اليدوية. صور TMDb المؤقتة ومفاتيح TMDb/Gemini لا تُنقل؛ أدخل الرموز السرية مرة أخرى داخل Settings.
9. اختبر فيلمًا واحدًا وترجمته ثم فحصًا تجريبيًا قبل استعمال المكتبة الكبيرة.

## حماية إضافية
- لو v2 فيها أفلام أو توجد عملية Restore مؤجلة، سيرفض الاستيراد بدل الدمج أو المسح الصامت.
- مصدر v1 يُقرأ بنمط SQLite read-only ثم يُنسخ بواسطة Snapshot. ليس مطلوبًا حذف v1 أو تغيير اسمه.
- في حالة حدوث مشكلة، ارفع Diagnostic ZIP بعد مراجعته، وليس DB الأصلية أو أي API Key.
- Backups الناتجة عن v1 يجب أن تحتوي على manifest.json وmovievault.sqlite وفقط ملفات البوسترات المعروفة. الأرشيفات المشبوهة/المتضخمة تُرفض.
